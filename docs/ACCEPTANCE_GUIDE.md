# 验收指南：稳定性、弱网与发布冒烟

本文覆盖三件发布前必须做、且**只能在真实环境完成**的事：

1. [24 小时稳定性观测](#1-24-小时稳定性观测)——服务端跑一整天不泄漏、不静默重启。
2. [弱网与断线验收](#2-弱网与断线验收)——断线重连、补发、语音与牌局互不牵连。
3. [发布冒烟清单](#3-发布冒烟清单)——四端各跑一遍，重点覆盖历史上真机才暴露的问题。

自动化测试（`go test ./...`、`flutter test`、CI）只能证明逻辑分支正确，证明不了「一整天不泄漏」和「电梯里断网能回来」。三项各自的记录模板在文末，每次发布把填好的记录附在 Release 说明里。

## 1. 24 小时稳定性观测

### 1.1 观测什么

[`deploy/monitor/texas-soak.sh`](../deploy/monitor/texas-soak.sh) 周期抓取 `/metrics` 与 `/readyz`，写成 CSV，结束时给出判定。看的是**趋势**而不是瞬时值：

| 指标 | 异常形态 | 说明 |
|---|---|---|
| `texas_goroutines` | 连接回落后不回落 | 每连接的协程没退出，最典型的泄漏 |
| `texas_memory_heap_bytes` | 单调上涨不回落 | 有对象被长期持有 |
| `texas_process_start_time_seconds` | 发生变化 | 容器静默重启，之前的趋势作废 |
| `texas_snapshot_broadcast_failures_total` | 大于 0 | 有整桌收不到快照 |
| `texas_websocket_connections_active` | 无人在线却不为 0 | 连接对象没释放 |
| `/readyz` | 任何一次失败 | 期间出现过不可用 |

判定阈值取「相对观测期内最低点」的增长，而不是相对起点：服务刚启动时基数低，用起点会把正常预热误判成泄漏。默认 goroutine +200、堆内存 +256 MB，可用 `TEXAS_SOAK_GOROUTINE_GROWTH`、`TEXAS_SOAK_HEAP_GROWTH_MB` 调整。

### 1.2 准备

`/metrics` 需要令牌，写入 `/opt/texas/soak.env`（与游戏服务 `.env` 中的 `METRICS_TOKEN` 一致）：

```bash
sudo install -m 600 /dev/null /opt/texas/soak.env
```

用编辑器写入一行 `TEXAS_METRICS_TOKEN=你的令牌`。**不要**把令牌写进命令行，它会留在 shell 历史里。

同步脚本并赋予执行权限：

```bash
sudo install -m 755 deploy/monitor/texas-soak.sh /opt/texas/bin/texas-soak.sh
```

### 1.3 运行

观测要跑满 24 小时，必须放进 `tmux` 或 `nohup`，SSH 断开不能中断：

```bash
tmux new -s soak '/opt/texas/bin/texas-soak.sh 2>&1 | tee /opt/texas/soak/last-run.log'
```

先用短时长确认链路通，再开正式一轮：

```bash
/opt/texas/bin/texas-soak.sh --hours 0.05 --interval 30
```

脚本启动时会先抓一次 `/metrics` 核对指标名。服务端改名而脚本没跟上时，缺失项会被静默记成 0、整轮观测失去意义，因此这里直接快速失败。

中途 `Ctrl-C` 也会先输出判定再退出，退出码即判定结果（0 通过、1 不通过、2 配置错误），可以直接接进自动化。对已有 CSV 重新判定：

```bash
/opt/texas/bin/texas-soak.sh --report /opt/texas/soak/soak-20260902-000000.csv
```

### 1.4 观测期间要有真实负载

空转 24 小时证明不了什么——泄漏往往发生在连接建立与销毁的路径上。观测期内至少制造以下负载，并记录大致时间点：

- 完整打完 **20 手以上**，覆盖 2 人和 6 人两种桌型。
- 反复进出牌桌 **10 次以上**（含弃牌后离开、结算后离开）。
- 反复加入/退出语音 **10 次以上**。
- 制造 **3 次以上**客户端断线重连（直接杀掉 App 或断网）。
- 触发一次限流（例如连续输错密码），确认计数上升且服务未受影响。

结束时让所有人离线，等一个采样周期再看：**连接归零后 goroutine 应当回落到接近开局水平**。这一步是整轮观测里最关键的判断。

### 1.5 判定不通过怎么办

| 判定 | 先查什么 |
|---|---|
| 进程重启过 | `docker inspect texas-game-server --format '{{.RestartCount}} {{.State.OOMKilled}}'`、`docker logs --since 24h texas-game-server` |
| 出现过不可用 | 健康巡检是否已告警；数据库容器状态；同时段服务日志 |
| 广播失败 | 服务日志中的 broadcast 记录，确认是整桌失败还是单连接失败 |
| goroutine 泄漏 | 与连接数曲线对照；重点看断线重连和离桌路径 |
| 堆内存增长 | 与牌局数对照；确认是否为聊天历史、事件缓冲等有上限的缓存 |

## 2. 弱网与断线验收

### 2.1 客户端的既有机制

验收是在核对这些机制是否按设计工作，不是随便断网看看：

- 心跳每 **25 秒**一次；**75 秒**收不到任何服务端消息即判定断线并重连。
- 重连退避 **1 → 2 → 4 → 8 秒**封顶。
- 重连时带上 `lastSequence`；服务端在 `table.joined` 回 `resumedFromSequence`、最近 50 条聊天和当前语音成员。
- 序号不连续时客户端置 `sequence_gap` 并请求快照，服务端回补发或整份快照。
- 动作被拒绝后客户端**总是**重新拉一次快照，避免动作栏停留在过期版本。
- 结算后自动准备倒计时 **10 秒**（发两次 **15 秒**）；短暂断线不等同于取消准备。
- 语音走 TRTC，与牌局 WebSocket 相互独立：**退出语音不会断开牌局，牌局断线也不应踢掉语音**。

### 2.2 如何制造弱网

| 平台 | 方法 |
|---|---|
| Web | Chrome DevTools → Network → 选 `Offline` 或 `Slow 3G`；WebSocket 需用 Offline 才会真正断开 |
| Android / HarmonyOS | 下拉通知栏开关飞行模式；或设置里禁用 Wi-Fi 与蜂窝 |
| Windows | `Disable-NetAdapter -Name "Wi-Fi" -Confirm:$false`，恢复用 `Enable-NetAdapter` |

服务端侧的丢包模拟（`tc netem`）不必做：本项目要验证的是客户端恢复路径，直接断网更接近真实场景（电梯、地铁、切后台）。

### 2.3 验收场景

每条都记录「实际现象」和「是否通过」。**加粗**部分是判定依据。

**A. 轮到自己时断线 5 秒**
断网 5 秒后恢复。预期：连接状态条显示重连并自行恢复；**行动截止时间由服务端权威给出，不因断线延长**；若期间超时，服务端按规则自动处理（过牌或弃牌），恢复后快照与之一致，客户端不出现「本地还能操作」的错觉。

**B. 轮到自己时断线 90 秒**
超过心跳判定阈值。预期：客户端进入重连；恢复后**手牌、底池、公共牌、筹码与其他玩家看到的完全一致**；这一手若已结束，直接进入下一手的准备状态。

**C. 结算瞬间断线**
在摊牌动画期间断网 20 秒。预期：恢复后**筹码结算结果正确且只结算一次**；自动准备倒计时按服务端剩余时间显示，不从头开始。

**D. 断线跨越自动准备倒计时**
结算后立刻断网 20 秒（超过 10 秒倒计时）。预期：**短暂断线不等同于主动取消准备**，恢复后状态与服务端一致；主动发送取消准备才会退出本轮。

**E. 后台驻留后回到前台**
把 App 切到后台 5 分钟再回来（手机上最常见）。预期：回到前台后自动重连并拉到最新快照，**不需要手动退出重进房间**。

**F. 弱网下连续操作**
`Slow 3G` 下连续点击加注、过牌。预期：**同一动作不会被提交两次**（动作有唯一 `actionId` 与幂等缓存）；被拒绝时给出中文提示并自动重新同步。

**G. 语音与牌局互不牵连**
- 牌局 WebSocket 断线时，**语音应继续通话**。
- 主动退出语音时，**牌局不断线、不影响行动**。
- 语音断线重连后，其他人看到的开麦状态与实际一致。

**H. 中途加入 + 断线**
牌局进行中加入房间成为「待入座」，随即断线重连。预期：恢复后仍是待入座、**收不到任何底牌**，本手结算后正常获得座位。

**I. 弃牌后离开 + 断线**
弃牌后点离开，立刻断网。预期：恢复后**筹码返还只发生一次**，钱包与流水对得上。

### 2.4 事后核对

弱网验收结束后跑一次对账，确认筹码守恒没有被异常路径破坏：

```bash
/opt/texas/bin/texas-reconcile.sh
```

## 3. 发布冒烟清单

四端各跑一遍。历史上这些问题**只在真机暴露**，自动化测试全绿也必须逐条走。

### 3.1 通用（每端都要）

- [ ] 版本号正确：关于页/包信息显示 `0.2.0`，HarmonyOS 的 `versionCode` 已同步。
- [ ] 注册页与个人信息页能打开《隐私说明》。
- [ ] 注册 → 登录 → 建房 → 加入 → 打完一手 → 离桌 → 退出登录，全程无异常。
- [ ] 钱包流水中文显示正确，无英文原始码（例如不应出现 `account_deletion`）。
- [ ] 管理员能进「服务器管理」和「审计记录」；**普通玩家看不到入口**。

### 3.2 牌桌布局（历史重灾区）

- [ ] **2 人、6 人、10 人**三种桌型座位排布正确，无重叠、无溢出。
- [ ] 图层顺序：公共牌背景 < 玩家框 < 本轮下注筹码 < 赞赏/嘲讽气泡。
- [ ] 本人手牌和摊牌在**玩家框内**；两块公共牌不遮挡任何玩家的摊牌。
- [ ] 发两次：两块牌面先后展示完整，自动准备倒计时为 **15 秒**。
- [ ] 窄窗口 Windows 与手机横屏下动作栏、聊天、语音控件都可达。

### 3.3 键盘与安全区（Android / HarmonyOS 必测）

- [ ] 登录页、大厅页弹出软键盘：**布局不抽搐、输入框不失焦、键盘不自动收回**（平板尤其要测）。
- [ ] 金额与房间码输入：HarmonyOS 使用自定义横屏数字面板。
- [ ] 挖孔屏安全区正确避让，牌桌内容不被摄像头挖孔遮挡。

### 3.4 语音

- [ ] 加入语音后双向可听；**HarmonyOS 重点验证开麦后能否持续听到其他人**（历史上音频路由会被抢占）。
- [ ] 单独静音某人、屏蔽某人分别生效；**取消屏蔽后仍处于静音的人不应恢复出声**。
- [ ] 退出语音不断开牌局。

### 3.5 交互

- [ ] 换位：两手之间点击其他玩家发起申请，对方确认后生效；**未坐满时也能发起**。
- [ ] 私下看牌：已弃牌玩家申请查看，对方同意后仅申请者可见，标签显示「私下查看」。
- [ ] 中途加入显示为「待入座」，本手结算后入座。
- [ ] 补码：筹码归零时自动弹出，金额上限正确。
- [ ] 注销账号：房间内应拒绝并提示；房间外注销后原用户名可重新注册。

### 3.6 打包与签名

- [ ] Android Release 使用正式签名（`android/key.properties` 已配置），**能覆盖安装上一版本**。
- [ ] HarmonyOS Release 签名可用，能安装到真机。
- [ ] Web 构建在目标浏览器可用，WebSocket 与 TRTC 均连通。
- [ ] 安装包不包含任何 `.env`、密钥或证书。
