# 好友德州 v0.8.0

新增**牌局回放**：在「牌局记录」里把自己打过的任意一手像录像一样逐步重放。**数据库、服务端、客户端三处都要更新**，顺序见文末「升级须知」。

## 玩家看到什么

- 大厅的「最近牌局」改名为「**牌局记录**」，不再只有最近 20 手：拉到底点「加载更早的牌局」可以一直往前翻。
- 展开任一手，点「**回放这一手**」进入回放页：
  - 第一帧是发牌与盲注，之后**每名玩家的每一次行动是一步**；发出翻牌、转牌、河牌，全下后补发或发两次，无人跟注的退回，摊牌，分池，也各是一步。
  - 可以播放/暂停、上一步/下一步、拖动进度条、切换速度（1×、2×、0.5×），放到最后自动停下。
  - 每一步都显示当时各人的筹码、本轮下注、底池和公共牌，画面与真实牌桌一致；控制栏写明这一步发生了什么，例如「对手（BB） 加注至 120」「我（SB） 弃牌（超时自动）」。
- **回放里只看得到自己的底牌，以及摊牌时亮出的牌**。别人没亮过的牌从头到尾都看不到；结算后自愿亮牌、私下看牌也不会出现在回放里。这条由服务端保证，客户端根本拿不到没亮过的牌。
- 升级之前打过的牌局同样能回放。

## 实现要点

- 牌谱只存了动作和最终结果，回放的每一步（筹码、底池、本轮下注）由服务端按规则重算。**算完后用牌谱记下的结束筹码逐人核对，对不上就拒绝回放**（提示「这手牌的记录不完整，无法回放」并写服务端日志），绝不给看一份算错的录像。无人跟注的退回与牌局结算用的是同一个分池函数。
- 盲注以前不是动作，从这一版起牌谱记下大小盲额与大小盲座位；超时代为过牌或弃牌的动作带上标记。旧牌谱的盲注额由迁移从房间补上，盲注座位按规则从庄位推出（两人桌庄位是小盲）。
- 回放画面直接复用对局的牌桌组件和同一套画布尺寸，手机横屏的布局、图层顺序与对局时相同。控件不跟着牌桌一起缩放：手机横屏时不占标题栏，返回键、房间号和这一步的说明放在左栏，进度条和播放按钮放在右栏，按钮保持正常大小；挖孔与手势条的避让与对局页一致。
- 摊牌亮出的牌（包括自己的）只在摊牌那一步之后按亮牌样式显示，之前的步骤不会提前透露牌型；换街后座位上只保留「弃牌」，不会出现「跟注至 0」；结算那一步的底池显示分出去的总额。

## 同时修复

- **上一手结算没入账时，几种操作会让牌桌永久卡死**（0.6.2 起就存在，本次审查发现）。一手结束时写库若失败，要等下一次有人点准备才补做。这期间：
  - 有人进观战或离开（包括被房主请出、被管理员移出），他会被移出引擎，补做时少了他，筹码守恒校验永远失败，这张桌再也开不了局；
  - 本手弃牌后离开、正等结算的人回到原房间，会按这一手之前的筹码被加回牌桌，之后每一手都结算失败。

  现在：换座、接受换座、进观战在这个窗口里被拒绝（与补码一样回 `settlement_not_persisted`，提示先点一次准备）；离开时服务端先把上一手补做完再让人走；等结算的离开者回房时先补做、完成他的离开，他再重新带入加入即可。从观战上桌不受影响。数据库恢复后一切照常。

## 接口与协议

- `GET /v1/hands/recent` 增加 `before` 参数：填上一页最后一手的手号，返回更早的一页（按结束时间与手号排序，不重复、不遗漏）。不传时与以前一样返回最新一页。
- 新增 `GET /v1/hands/{handId}/replay`：返回按请求者裁剪的回放时间轴（每一步的完整桌面状态）。
- 新错误码：`hand_not_found`（404，手号不存在或请求者不在这手牌里，两者不区分）、`replay_unavailable`（422）。
- 牌谱（`hands/recent` 返回的每一手）增加 `smallBlind`、`bigBlind`、`smallBlindSeat`、`bigBlindSeat`，动作增加 `timedOut`（为真时才出现）。

## 升级须知

1. **备份后先跑数据库迁移 `000013_hand_replay`，再启动新服务端。** 迁移给 `hands` 加四列并从房间补上旧牌谱的盲注额、给 `hand_actions` 加 `timed_out`、为翻页建一个索引。补盲注额要扫一遍 `hands`，牌谱很多时会多花几秒。
2. 更新服务端并重启。旧客户端照常使用，只是没有回放入口。
3. 分发 0.8.0 客户端；所有人装好后可以把「最低客户端版本」填成 `8000`。这一版没有必须强制升级的原因，不填也可以。
4. 建议在服务器上按 `PRODUCTION_UPDATE_GUIDE.md` 的「可选：运行真实 PostgreSQL 集成测试」一节跑一遍：这次改了牌谱的读写与迁移。

## 测试

- **随机属性测试**：用真实的牌桌管理层在 2、3、6、9 人桌各随机打一百二十手，然后从每一位参与者的视角回放每一手，要求：自检通过；任何一帧都不出现请求者看不到的底牌；按规则推出来的盲注座位与引擎实际用的一致；动作一个不少。下注、加注、全下、弃牌、真正由服务端代为行动的超时、发两次、抽水按落库的牌谱统计，退回与摊牌按生成的回放统计，每种都必须出现，没出现测试就失败。开发时把生成器改坏（去掉退回、颠倒两人桌盲注、放开底牌可见性）和去掉超时标记，都确认过这些断言会失败（手工验证，不在仓库里）。
- 回放生成器单元测试：翻牌前全弃与退回、换街清空动作、两人桌推盲注、五种对不上账的牌谱一律拒绝。
- 牌谱存储：按接收者裁剪的契约扩展到单手读取与翻页；翻页在同一时刻结束的几手之间不重复不遗漏；局外人查不到别人的手，也不能拿别人的手号当游标。
- 真实 PostgreSQL（CI）：新列往返；迁移给旧牌谱补盲注额（包括已关闭的房间）。
- 传输层端到端：两人打到摊牌后各自取回放，本人的牌每一帧都在、对手的牌只在摊牌后出现；局外人、未登录、不存在的手号分别返回 404/401/404；对不上账的牌谱返回 422。
- 结算没入账的窗口里补码、换座、进观战都被拒绝，从观战上桌照常；离开会先补做结算；等结算的离开者回房会先补做并完成他的离开，之后重新加入、下一手照常入账（这两个场景的测试在修复前都会失败）。
- 客户端：时间轴解析、每一步的中文说明（含下注、加注、全下、退回、发两次、抽水）、底牌与牌型只在该出现时出现、本街没有投入时不显示带金额的动作、结算底池、回放页在 1280×720 / 900×430 / 740×340 下前进后退拖动播放都不溢出、手机横屏按钮不小于 40 像素、九人桌长昵称在 740×340 到 1280×720 及 480×900 竖窗共七种尺寸下两侧面板都不压玩家框、读取失败可重试且错误都是中文、牌局记录翻页与回放入口。

## 已知边界

- 发两次时回放直接显示两块牌面，不演示协商过程；加时卡不进入回放。
- 回放显示的是牌谱记录时的昵称。
- AI 复盘尚未开发，见 `docs/decisions/ADR-003-HAND-REPLAY-AND-AI-REVIEW.md`。
