# 好友德州 v0.9.0

新增 **AI 复盘**：管理员开通的账号可以在牌局回放里让大模型以教练视角点评自己这一手的每个决策。**数据库、服务端、客户端三处都要更新**，并且要在服务端配置大模型的密钥，顺序见文末「升级须知」。

## 玩家看到什么

- 被开通的账号，在回放页右下角多一个「**AI 复盘**」按钮。点下去右侧弹出复盘面板，显示「正在分析」，通常半分钟到两分钟后自动出结果，期间可以关掉面板继续看回放：
  - **总评**：这一手整体打得怎么样；
  - **牌局概况**：几人桌、盲注级别、你的位置与底牌、每家的起始码量（由服务端按交给 AI 的同一份数据填写，可以核对 AI 看到的桌面）；
  - **逐步点评**：自己的每一次行动一条，结论是「好」「合理」「有争议」「失误」之一，附分析和**最佳行动**（每一步都给，本次已是最佳也会写明）；每一步还列出服务端算好的精确数字——底池、需跟注额与跟注所需的最低胜率、SPR、当时的牌力（最好的五张、用到哪几张底牌）、对随机手牌的胜率；以及标明「AI 估算」的对手范围胜率、本次行动与最佳行动的期望收益（以大盲计，最佳比本次多赚多少）；点一条就跳到回放里的那一步；
  - **要点**、**对手倾向**（结合对手在你们同桌打过的牌局里的打法统计）、**结果回顾**（摊牌亮出的牌与最终结果）。
- 回放到有点评的那一步时，左侧说明栏显示「AI：失误」这样的结论和一段摘要，点一下打开完整复盘。
- 同一手只分析一次，之后再打开按钮变成「查看 AI 复盘」，直接看结果、不重复计次。分析失败会写明原因（例如「大模型服务暂时不可用」），可以重新分析。
- 自己在这一手里一个决定都没做（例如大盲时所有人弃牌）的手没有复盘入口。
- 没开通的账号看不到这个按钮，回放照常使用。

## 管理员看到什么

- 「服务器管理」右上角新增「**AI 复盘管理**」：
  - 显示服务端是否配置了大模型、用的是哪个型号；
  - 总开关，每人 24 小时内的次数上限，全服最近 30 天的 token 总额（0 为不限，默认都不限）。**失败的复盘不占每人次数**（否则上限为 1 时赶上一次模型出错就再也不能重试），但失败消耗的 token 照样计入全服总额；
  - 最近 24 小时 / 30 天的请求次数与 token 用量；
  - 玩家名单，逐个开通或收回。开通与设置变更都记入审计记录。管理员账号不能上桌、没有自己的牌局，所以不在名单里。
- 关掉总开关后所有人都不能发起或查看复盘；已有结果保留，重新打开后仍可查看。已经在排队的也不会再调用模型（收回某人权限、全服额度用完时同理），记为失败，之后可以重新发起。

## 实现要点

- **数字由服务端算，模型只做判断**。每个决策点的底池、需跟注额、底池赔率、有效筹码、SPR、成牌与同花听牌、对随机手牌的胜率（蒙特卡洛两千次，种子由手号决定，同一手每次算出来一样）都先算好再交给模型，提示词要求直接使用、不得自己重算或编造。大盲筹码不足全下时，翻前需跟注额仍按完整大盲算（与引擎一致）；SPR 只用双方还没投进底池的筹码；本人筹码比对手投入少时（例如短码面对全下）另给「本人最多能赢到的底池」，赔率按它算，否则赔率会被严重低估。
- **EV 与范围胜率是估算**：对手范围胜率与两个 EV 由模型按提示词给的口径估算（跟注 ≈ 范围胜率 ×（底池 + 需跟注）− 需跟注，弃牌为 0，大盲计），服务端只做合理性检查：超出范围、最佳行动的 EV 比本次还低、或最佳行动的 EV 为负（弃牌永远是 0）这类自相矛盾的，不显示。界面上一律标成「AI 估算」，与服务端算出的精确数字分开。
- **牌力也由服务端给出**：每个决策点附上本人最好的五张牌和其中用到的底牌（公共牌本身就是这个牌力时注明）。只给牌型名时，模型曾把 A2 在 KK553 上的「K 和 5 两对、A 踢脚」说成「AA KK」。
- **对手倾向只用双方同桌打过、且在这一手之前的牌**：入池率、翻前加注率、翻后激进度、摊牌率，只统计请求者与该对手都在的手、只用公开动作，最多往回看 300 手；这一手本身和之后才打的牌是决策当时不知道的，不计入。没超过当前最高投入的全下按跟注算，不抬高短码玩家的加注率。样本不足 30 手时要求模型注明。
- **发给模型的数据不含身份**：只有位置、筹码、牌与动作，没有用户名、昵称、账号或房间号；数据取自与回放相同的按请求者裁剪的牌谱，没亮过的底牌根本不在里面。摊牌亮出的牌放在单独的「事后」一节，提示词要求点评决策时不得使用，只用于「结果回顾」。
- **兼容任何 OpenAI 接口的大模型**：请求 `{REVIEW_BASE_URL}/chat/completions`，默认 DeepSeek `deepseek-reasoner`。默认要求 JSON 输出，服务不支持 `response_format` 而报 400 时自动去掉重试；输出不合格式时重问一次，仍不行记为失败。逐步点评只保留确实是本人决策的步骤；结论的常见同义说法（「错误」「不合理」「标准」等，带引号或括号也认）归一到四档，**漏写结论或写了认不出的结论都算不合格**——实测 DeepSeek 偶尔把输入字段抄回来、漏掉结论，若默认成「有争议」，明确的失误也会显示成争议。输出到了长度上限（`finish_reason` 为 `length`）记为「超出输出长度上限」，不再重问。`REVIEW_BASE_URL` 写错时服务拒绝启动。
- **排队处理**：请求写入数据库排队，由服务端一个后台协程逐条分析。服务重启时把「进行中」的放回队列；停机时做完手上那一条再退出（在排空牌桌的同一时限里等它），模型已经在生成的内容不白付钱。结果存库失败先隔几秒重试，一直存不进去就退一步记为失败（`internal_error`）；连失败也记不上时，没人在处理的「进行中」对玩家显示为失败、可以重新发起，不会一直转圈到服务重启（重新发起时只改仍是「进行中」的那一条，后台恰好做完的不会被覆盖；进程刚启动、上次留下的还没放回队列时不做这个判断）。后台协程每次读写数据库都有 10 秒时限，连接半开时不会把整个队列卡住。模型服务的报错按字符截断并去掉数据库拒收的字符后再存。失败原因只以原因码返回客户端，模型服务的报错原文只写服务端日志。
- 提示词带版本号，结果按「这一手 + 这个人 + 提示词版本」缓存；以后改进提示词会升版本，玩家可以用新版重新分析。

## 接口与协议

- 新增 `GET /v1/review/access`、`POST|GET /v1/hands/{handId}/review`、`GET /v1/admin/review`、`POST /v1/admin/review/settings`、`POST /v1/admin/review/access`，说明与错误码见 `docs/WEBSOCKET_PROTOCOL_V1.md` 7.8。
- 新错误码：`review_unavailable`（503）、`review_not_allowed`（403）、`review_daily_limit` 与 `review_budget_exhausted`（429）、`review_not_found`（404）、`review_no_decisions`（422）、`invalid_review_settings`（400）；发起复盘时这手牌无法还原成回放返回 `replay_unavailable`（422）。复盘失败原因新增 `output_truncated`。
- 新审计事件：`admin.review_settings_changed`、`admin.review_access_changed`。

## 升级须知

1. **备份后先跑数据库迁移 `000014_hand_review`，再启动新服务端。** 迁移只新建三张表（设置、开通名单、复盘任务），不改动已有数据。
2. 在服务端环境文件里加上 `REVIEW_API_KEY`（必填，留空则整个功能不出现），按需加 `REVIEW_BASE_URL`、`REVIEW_MODEL`、`REVIEW_TIMEOUT_SECONDS`、`REVIEW_JSON_MODE`、`REVIEW_MAX_TOKENS`，含义见 `.env.example` 与 `docs/SELF_HOSTING_GUIDE.md`。服务器需要能出站访问大模型服务的地址。
3. 更新服务端并重启。旧客户端照常使用，只是没有复盘入口与管理页。
4. 分发 0.9.0 客户端，管理员在「AI 复盘管理」里给要用的账号开通。所有人装好后可以把「最低客户端版本」填成 `9000`；这一版没有必须强制升级的原因，不填也可以。
5. 建议在服务器上按 `PRODUCTION_UPDATE_GUIDE.md` 的「可选：运行真实 PostgreSQL 集成测试」一节跑一遍：这次新增了三张表的读写。

## 隐私

- 隐私说明（客户端对话框与 `docs/PRIVACY_NOTICE.md`）增加两条：保存复盘结果；发起复盘时这一手的局面数据会发给搭建者配置的大模型服务，并写明发送与不发送的内容，**包括同桌的人发起复盘时，没用这项功能的玩家在那一手里的公开信息与打法统计也会被发出**。按 ADR-003 的决定，不另加首次使用弹窗。
- 新增测试逐条比对客户端对话框与文档，两处不一致时 CI 失败。

## 测试

- 服务端：开通名单与总开关的访问规则；本人没行动过的手被拒绝；结论同义词归一、漏写结论算不合格；短码跟注按能赢到的底池算赔率；最好五张与用到的底牌；旧牌谱推出盲注座位后再判断全下是加注还是跟注；数据库断开时重试存结果、没人处理的「进行中」可以重新发起、正在处理的不会被误判；输出被截断；同一手只分析一次并缓存；排队期间关总开关、收回权限、额度用完都不再调用模型；失败不占每人次数、重新排队期间 token 仍计入预算；结果存不进去时记失败而不是卡在进行中；中文报错按字符截断；模型答完才停机的结果照样保存；对手倾向只用这一手之前的牌；短码大盲时的需跟注额与赔率；全下按实际作用归为加注或跟注；设置上限；发给模型的内容不含用户名、账号、房间号与没亮过的牌；输出不合格式时重问一次、两次都不行记失败且可重新发起；模型服务报错原文不外泄；每人次数与全服 token 额度；第一个决策点的底池、需跟注、赔率、SPR 精确值；对手倾向只统计同桌的手；解析各种不合格输出。
- 真实 PostgreSQL（CI）：设置、名单、排队、领取、重启放回、失败重试、结果 JSON、token 累计与用量统计的往返；失败的不占次数、重新排队期间 token 仍计入预算。牌局记录的迁移回退测试改为按迁移数计算步数（此前写死退一步，加了 000014 之后会退错）。CI 与生产更新指南的定向集成测试加上了复盘仓储。**本机没有 Postgres，这部分只能在 CI 或可丢弃的测试库上跑。**
- 传输层端到端：管理员开通 → 两人打到摊牌 → 发起 → 后台分析 → 取回结果；未开通被拒、看不到入口，普通玩家不能改名单与设置，设置漏传字段被拒，开通记入审计。
- 客户端：未开通或本人没行动过的手不显示入口；分析中被收回权限时停止轮询并说明原因；发起后排队、轮询出结果并在出结果后停止轮询，点逐步点评跳到那一步并显示结论；已有结果直接可看、不重复发起；额度用完与分析失败的提示和重试；九人桌在七种尺寸下带上复盘按钮与点评仍不压玩家框；管理页的模型状态、用量、名单开关、设置校验、读取失败时不把「没取到」显示成「没开通」；接口解析；审计记录的中文说明；隐私说明两处一致。

## 已知边界

- 复盘质量取决于所用模型；胜率是对随机手牌的估算，只作参考。
- 提示词用 DeepSeek `deepseek-reasoner` 调过：用真实牌桌管理层让紧凶、跟注站、疯子、岩石、常规五种风格的机器人打 220 手，挑本人摊牌、全下、翻前多次加注、河牌弃牌、多人底池、超时、发两次、输大底池八类手各一手复盘，前两轮对比后修了漏写结论、牌力误读、事后信息混进对手分析三个问题，第三轮加上了每一步的最佳行动与 EV 估算。加上 EV 估算后，每手约 30～100 秒，输入约 2.5～3 千、输出约 5～18 千 token（含思考过程），输出量大约是只做点评时的两倍。结果回顾里偶尔仍会把摊牌者的牌型说错（例如把公共牌的对子说成手里的对子），以亮牌数据为准。机器人打法不代表真人，真实牌局上线后仍应抽查几手。
- 每人次数是「先查后写」，同一个人几乎同时发起不同的手时可能略超上限；熟人规模下影响很小。
- 分析由单个后台协程串行处理，多人同时发起时要排队。
