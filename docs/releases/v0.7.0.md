# 好友德州 v0.7.0

新增**抽水**：管理员可以按房间设置每手从底池里抽走一部分娱乐筹码，进入管理员账户。**数据库、服务端、客户端三处都要更新**，且有先后顺序，见文末「升级须知」。

## 规则

管理员在「服务器管理 → 抽水管理」里给每个开着的房间单独设置，房主不能改。新房间默认不抽。

| 设置项 | 含义 |
|---|---|
| 开启抽水 | 总开关 |
| 比例 | 每手按底池的百分之几抽，0%～10%，步长 0.25% |
| 封顶筹码 | 按比例抽的部分最多抽多少；留空为不封顶 |
| 翻后加抽 | 开关。发出翻牌的手额外再抽一笔 |
| 加抽筹码 | 加抽的固定数额，**不受封顶限制**，但不能超过一个大盲 |

计算细则：

- **底池按标准规则计**：没人跟注而退回的筹码不算。例如翻牌前 A 加注到 100、其余人都弃牌，A 多出来的部分先退回，只对真正被争夺的盲注部分抽。
- 比例部分**向下取整**，再与封顶取小；翻后加抽在此之上另加，所以一手最多抽「封顶 + 加抽」。
- 「发出翻牌」按这一手结束时桌上有没有至少 3 张公共牌判断。翻牌前全下、随后补发公共牌的手也算。
- **底池不足两个大盲的手不加抽。** 短码在盲注位全下、随后补发公共牌时，底池可能只有几个筹码，一个大盲的加抽会把它整个抽走。
- 一手只抽一次，发两次也是对整个底池抽一次。
- **有边池时按各池大小分摊**，零头逐枚补给小数部分最大的池。最初的设想是从主池起依次扣，独立审查指出那样不公平：短码全下的人只能争主池，却要一个人替边池付掉全部抽水，主池甚至会被扣到 0——牌最大却一分拿不到。
- 修改**从下一手起生效**，进行中的一手按开局时的规则结算；服务端中途重启恢复出来的那一手也一样。
- 看牌费不抽水。

### 取整与筹码守恒

向下取整不会丢筹码：抽走的是一个整数，玩家合计少拿的正是这个整数。此前「各人输赢之和为 0」的校验改为「各人输赢之和 + 本手抽水 = 0」，在规则引擎、牌谱入库和钱包事务三处同时校验；抽水进管理员钱包与该手结算在**同一个数据库事务**里完成，要么都成、要么都不成。管理员账户多一种流水「牌桌抽水」，每手一条，可逐条对账。

## 玩家看到什么

- **规则一变，房间文字聊天里出现一条「系统公告」**，写明比例、封顶、翻后加抽和「下一手起生效」。公告不是哪位玩家发的：伪造不了，也不受屏蔽名单影响；聊天没开着时另有一条提示，未读角标同样会加一。
- **每手结算区写明「本手抽水 X」**，分到各人手里的数额已经扣过它。「最近牌局」里也标出每手的抽水。
- **牌桌信息栏常驻显示当前规则**（例如「抽水 5%，最多 50；翻后加抽 10」），不抽时不显示。公告会被后面的聊天刷走，后来才进房间的人靠这一行随时看得到。
- **加入房间前就能看到**：输入房间码后的带入窗口里写明「本房间抽水：…」。

## 管理员看到什么

- 「抽水管理」页上半部分是开着的房间：房间码、盲注、房主、人数、当前规则和已抽总额，点「设置」修改。
- 下半部分是**按房间的累计抽水**，包含已经关闭的房间，并有合计。上方可填「多少元 = 多少筹码」做换算——与「本房间战绩」一样**只在本机计算**，服务端不存储也不传输任何金额。
- 每次修改规则都记入审计记录。
- **管理员账号不能再创建或加入牌桌**（服务端拒绝，大厅也会说明原因）：收抽水的人不能同时坐在桌上。管理员自己想打牌请另注册一个普通账号。
- 抽水打进**最早创建的、状态正常的管理员**的钱包。没有这样的管理员时不抽，而不是抽了没处放；这位管理员自己就在那个房间里时（升级前就坐着）那个房间也不抽。

## 接口与协议

- `GET /v1/admin/rooms`：开着的房间及各自的规则、累计。
- `POST /v1/admin/rooms/{roomID}/rake`：设置规则。`enabled`、`basisPoints`（万分比）、`cap`、`postflopEnabled`、`postflopAmount` 五个字段必须传齐，漏传返回 `invalid_rake_settings`，不会被当成关闭。
- `GET /v1/admin/rake`：按房间的累计抽水与合计。
- 结算快照 `settlement` 增加 `rake`、`rakeBase`（仅有抽水时出现）；最近牌局的每手增加 `rake`。
- 快照顶层与 `GET /v1/rooms/preview` 增加 `rake`：房间当前的抽水规则。
- 聊天消息增加 `kind=system`，只由服务端发出。
- 新错误码：`admin_cannot_play`（403）、`invalid_rake_settings`（400）。

## 升级须知

1. **升级前，管理员账号先离开所有房间。** 升级后管理员不能再进房间。仍留在桌上的管理员可以继续打完并离开，但只要收款的管理员还在某个房间里，那个房间就不会抽水。
2. **先跑数据库迁移 `000012_rake`，再启动新服务端。** 迁移给 `rooms` 加五列（默认不抽）、`hands` 加 `rake`、账本与聊天的类型约束各放开一项。迁移前照常备份。这个迁移**一旦产生了抽水流水就不能回滚**——账本是不可变的。
3. 更新服务端并重启。此时不开抽水的话，旧客户端一切照常。
4. 分发 0.7.0 客户端。**在所有人装好、并把「最低客户端版本」填成 `7000` 之前不要给任何房间开抽水**：旧客户端不显示「本手抽水」，也不认识系统公告，玩家会觉得分到手的筹码莫名其妙少了。
5. **把服务器上的对账脚本换成新版**：`sudo cp deploy/backup/texas-verify.sql /opt/texas/bin/`。旧版的 `settlement_per_hand` 要求每手结算流水之和为 0，会把每一手抽过水的牌都报成不平衡；新版按「结算流水 + 该手抽水 = 0」判断。不开抽水时新旧版结果相同。
6. 建议在服务器上按 `PRODUCTION_UPDATE_GUIDE.md` 的「可选：运行真实 PostgreSQL 集成测试」一节跑一遍：这次改了三个 PostgreSQL 仓储。

## 测试

- 规则引擎：比例/封顶/加抽的数值表（含不足两个大盲不加抽）、各池按比例分摊与零头、短码全下的主池赢家只付主池那份、弃牌收池、无人跟注的全下、摊牌、边池、崩溃恢复、默认不抽。
- 钱包：抽水与结算同事务、守恒式、重复结算幂等、按房间汇总。
- 牌桌管理层：抽水进管理员钱包、快照带当前规则、下一手才生效、没有管理员或收款人就在房间里时不抽、手中途重启后按原规则结算。
- 传输层端到端：管理员设置 → 玩家收到聊天公告 → 打一手 → 结算写明抽水 → 管理员钱包到账 → 后台汇总；房主改不了、漏传字段被拒、加抽超过大盲被拒、管理员不能建房/进房；玩家伪造系统公告被拒。
- 真实 PostgreSQL（CI）：新列往返、约束、同事务入账、`rake` 流水、牌谱、房间关闭后仍可按房间码汇总、`system` 聊天类型，以及按生产对账脚本的口径逐手平衡。
- 客户端：结算区与牌谱的抽水显示、聊天面板里公告不受屏蔽名单影响且无屏蔽入口、牌桌信息栏与加入预览显示规则、设置窗口的校验与矮屏布局、抽水管理页的列表/合计/换算及「一个请求失败不拖累另一个」、大厅对管理员的拦截、审计文案。

## 已知边界

- 抽水只打给一位管理员（最早创建的那位）；多位管理员之间如何分配不在系统内处理。
- 累计抽水按房间汇总，不按日期或按玩家拆分；需要更细的口径可以直接查 `bankroll_entries` 里 `reason = 'rake'` 的流水。
- 比例在界面上以 0.25% 为步长；接口本身接受任意万分比。
